# go-katas

Учебный репозиторий для прокачки Go: конкурентность, примитивы синхронизации, паттерны и небольшие прикладные задачи.

Здесь я разбираю классические примитивы «с нуля» (часто на каналах, без `sync`), пишу свои аналоги стандартных инструментов и закрепляю это на задачах ближе к реальному коду — HTTP, БД, воркеры.

Часть заданий вдохновлена курсовыми/практическими катами (в т.ч. экосистема [shad-go](https://github.com/slon/shad-go)): формулировки задач и тесты — учебный материал, реализации — мои.

## Зачем этот репозиторий

- Понять, как устроены `Once`, `WaitGroup`, `Cond`, `RWMutex` «изнутри»
- Набить руку на гонках, deadlock’ах, отмене через `context`, утечках горутин
- Закрепить паттерны: singleflight, rate limit, pub/sub, batching, key-based locking
- Сравнивать подходы бенчмарками (семафор vs worker pool)
- Переносить навыки в прикладной код (опрос HTTP, проверка платежей)

## Быстрый старт

```bash
git clone https://github.com/ZhdanovichVlad/go-katas.git
cd go-katas
go test ./...
```

Отдельный пакет:

```bash
go test -v -race ./pubsub/
go test -v -race ./sync_once/
```

Требуется Go (см. `go.mod`, сейчас `1.26.x`).

Профили (`cpu.out`, `mem.out`), дампы `benchstat` (`new.txt` / `old.txt`) и локальный IDE-мусор **не коммитятся** — см. [`.gitignore`](./.gitignore). Результаты бенчей лучше держать в README пакета (как в `http_survey`) или в CI-артефактах.

## Карта репозитория

### 1. Примитивы синхронизации (с нуля)

Реализации «как в `sync`», но обычно **на каналах**, без использования пакета `sync` внутри самой задачи.

| Ката | Что тренирую | Папка |
|------|----------------|-------|
| **Once** | Ленивая инициализация, ровно один запуск `f`, ожидание остальных | [`sync_once/`](./sync_once) |
| **WaitGroup** | Счётчик горутин, `Add` / `Done` / `Wait`, переиспользование | [`waitgroup/`](./waitgroup) |
| **Cond** | Ожидание условия, `Signal` / `Broadcast`, FIFO очередь | [`cond/`](./cond) |
| **RWMutex** | Много читателей / один писатель, без busy-wait | [`rwmutex/`](./rwmutex) |

### 2. Конкурентные паттерны и утилиты

| Ката | Что тренирую | Папка |
|------|----------------|-------|
| **Rate limiter** | Не больше N успешных `Acquire` за интервал, одна управляющая горутина, `Stop` + `context` | [`ratelimit/`](./ratelimit) |
| **Dupcall** | Свой singleflight: дедуп дорогих вызовов, отмена `cb` только когда отменены все ждущие | [`dupcall/`](./dupcall) |
| **KeyLock** | Лок по множеству строковых ключей, пересечения множеств, отмена через канал | [`keylock/`](./keylock) |
| **Batcher** | Батчинг медленных `Load`, без stale reads | [`batcher/`](./batcher) |
| **Batcher v2** | Вторая итерация того же навыка | [`batcher_v2/`](./batcher_v2) |
| **Pub/Sub** | Топики, FIFO, медленный подписчик не блокирует остальных, `Close(ctx)` без утечек горутин | [`pubsub/`](./pubsub) |

### 3. Прикладные проекты

| Проект | Что тренирую | Папка |
|--------|----------------|-------|
| **HTTP Survey** | Опрос URL с лимитом параллелизма: семафор vs worker pool, cache, singleflight, retry budget, бенчмарки | [`http_survey/`](./http_survey) |
| **Payment status worker** | Code review → рефакторинг воркера статусов платежей: `FOR UPDATE SKIP LOCKED`, батчи, слои, миграции | [`checking_payment_status_via_API/`](./checking_payment_status_via_API) |

Подробности, требования и иногда результаты бенчей — в README внутри каждой папки.

## Как устроены каты

Типичный цикл:

1. Читаю условие в `README.md` пакета
2. Пишу реализацию
3. Прогоняю тесты: `go test -race ./<pkg>/`
4. Смотрю на гонки, зависания, `goleak` (где подключен)

Это не production-библиотека, а полигон: код может быть учебным, с упрощениями и итерациями (`batcher` / `batcher_v2`).

## Чему учусь на практике

- **Модель памяти и гонки** — `-race`, порядок записи/чтения, защита shared state
- **Каналы vs мьютексы** — когда что уместнее, как не словить deadlock
- **Отмена** — `context`, закрытие каналов, корректный shutdown
- **Backpressure и изоляция** — slow consumer, очереди на подписчика, batching
- **Идемпотентность и конкуренция в БД** — `SKIP LOCKED`, несколько реплик
- **Измерения** — `testing.B`, `benchstat`, понимание allocs/op



## Лицензия и использование

Учебный pet-проект. Формулировки отдельных заданий могут принадлежать авторам исходных курсов/катов — здесь лежат мои решения и заметки для обучения.

Если берёте идеи в свой код — адаптируйте осознанно: это упражнения, не готовая библиотека.
